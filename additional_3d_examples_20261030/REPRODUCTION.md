# 数据、源码与重画说明

本目录是六个预先固定三维形状的补充研究。原A17论文、closure数据以及之前的三维示例保持原样。这里没有N3或其他网络，也没有训练；所有重建从均匀复材料开始。

## 先读什么

1. `START_HERE.md`：主要结果、图像入口和阅读顺序。
2. `RESEARCH_REPORT_ZH.md`：最终材料误差、强对照及解释。
3. `METHODS_AND_INTERPRETATION_ZH.md`：物理模型、各方法到底比较什么、如何理解梯度回退和三维图。
4. `COST_AND_FAILURES.md`：累计费用、硬件切换、真实运行故障和未关闭问题。
5. `analysis/FINAL_METRICS.csv`：从原最终记录直接整理的逐对象、逐方法指标。

## 数组与指标

`inputs/<object>.npz`保存点坐标、复材料真值、均匀初值、清洁及带噪声测量、同一噪声实现与留出接收数据。`results/<object>/<policy>/final.npz`保存最后实际接受的材料；`final.json`保存其指标和真实终态，`trajectory.json`保存各次接受更新与梯度回退记录。`chi_XX.npz`是已接受材料检查点。A17各次交换的端点、finalist、定向核验与逐动作记录保留在完整原始归档中。

所有主表读取已保存的最终指标，不重新求解Maxwell，不按材料真值挑最好的中间帧。复材料NRMSE、实部/虚部误差、支撑IoU、测量及留出误差分别保留。第一列SYNTHETIC TRUTH永远不是重建。

全局账本的`states`准确计数的是以`full`标记的矩阵分解准入次数；`rhs`计数以`full`开头的完整求解调用中复右端列数。它们不是独立对象数，也不能直接当成JVP方向数。十二次照明下，一个定向Jd通常涉及多个电流RHS。失败和拒绝试探仍收费。

三条从检查点接续的轨迹，其最终模型内部counter只覆盖新进程部分。完整账本仍保留旧前缀和未提交tail的费用；汇总CSV另外按原账本stage提供完整的逐方法准入计数。并行阶段的子轨迹墙钟不能求和代替占用时间。

## 重画已有结果

公开目录中，`data/`是保存的数据与记录，`source/`保持原项目的相对源码布局。在安装有NumPy和Matplotlib的Python环境中：

```bash
python source/Gaussian/A17/SHAPES_3D_BASELINES_20261030/research/delegated/som/plot_results.py --root data
```

该脚本只读保存数组和记录，输出统一阈值三维体素图、原始Re/Im切片、最终误差表图和迭代曲线，不调用物理求解器。默认只输出三种原生中央切面，不平滑、不插值为高分辨率图像。三维体素图只显示Reχ≥0.5；评价完整材料误差时必须同时看切片和数值表。

本地研究目录也可直接运行同一脚本并将`--root`指向该目录。`collect_final.py`只整理已记录的JSON/账本；其ROOT绑定在脚本所在的研究目录，不能把它从相对目录中随意移走后仍期待读取同一组数据。

## 物理实现与源码范围

源码使用原三维矢量Maxwell DDA、真实极化率导数、共享多照明复材料、原Galerkin接口和原A17交换规则。新增的端点数值实现仅对同一正规方程做最多三次FP64残差精化，不改正则项、正常残差门槛、候选排序或接受准则。CUDA入口显式切换原物理后端和批量端点的设备；材料维数、物理方程和精度不因迁移改变。

公开源码按明确文件表原样复制，保留`Gaussian/A17/...`层级；没有对可执行算术表达式做脱敏替换。`SOURCE_FILES.json`给出所复制文件及bytes，不把文件大小当作内容或数值正确性证明。此研究没有另加SHA检查或发布重跑。

新的依赖闭包与原A17整篇论文的历史GPU依赖不是同一个范围。所附源码供审阅本研究和建立新的明确计费重跑；公开打包动作没有重新执行物理实验，也不构成跨平台逐位回放证据。历史多阶段交接需要的内部恢复计划不是无状态入口，不能直接运行`remote_serial_resume.py`并期待自动重现所有执行过程。

数值运行依赖NumPy、SciPy、threadpoolctl；CUDA路径另外依赖可用的PyTorch CUDA。远端实际环境是Python3.10.9、NumPy2.2.6、SciPy1.15.3、PyTorch2.6.0+cu124。Windows入口的P-core affinity只作用于本进程；代码没有安装或更改系统计算框架。

## 历史、资源与重跑边界

最初资源合同为7200秒，随后用户明确批准固定36条任务的累计上限为10800秒。原`CONFIG.json`保留最初记录；有效3小时资源覆盖在`CONFIG_EXTENDED.json`和最终资源说明中给出。物理、种子、对象、候选、秩和18次更新上限没有随延长而调整。

所有新物理重跑都应在新的空结果目录与新账本中显式计费。不要重置本研究的已关闭账本、覆盖历史输出，或运行被本研究仅作为helper导入的旧runner。原SOM/TSOM完整优化器没有在本实验中复现，receiver和projected-internal只能使用已声明的proxy标签。

真实运行异常及其原产物保留。特别是日志命名空间异常的根因尚未确定，不能因为fresh进程接续完成便认定它只影响日志或给旧前缀作独立数值背书。该限制与原A17的冻结证据分别说明。
