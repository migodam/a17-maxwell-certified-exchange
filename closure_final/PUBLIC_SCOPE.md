# Public scope and source identity

The published closure distinguishes four types of content:

1. Exact owned execution-source bytes, tied to actual runtime path/hash receipts. Executable numerical expressions are not redacted or rewritten.
2. Exact, specifically reviewed scientific metadata and saved numerical arrays. Approved benign research-directory paths remain byte-identical so that internal hash chains are preserved.
3. Newly named public reanalysis ports and derived fee tables. Their portability changes and independent source identity are recorded; they are not presented as historical runtime bytes.
4. Hash identities for 42 external physics/dependency modules whose bytes are not redistributed.

Private credentials, SSH configuration, complete process-command/CIM logs, transport originals, third-party full-text PDFs, caches and unreviewed dependency bytes are excluded. Public source does not undergo blanket string or regular-expression privacy replacement. Each included file is pinned by content hash and inclusion role; evidence-volume aliases preserve the relationship between deduplicated bytes and their saved paths.

The public package supports reanalysis of reported saved evidence. Full GPU replay needs the identified external kernels and original physical conventions. Private monitor-ledger re-audit requires the private closed snapshots; the public package instead exposes reviewed fee rows and a bound derivation scope.

The original development archive and fixed historical commit are preserved. Later closure source cannot retroactively prove which source a historical job imported; that binding is supplied by the job's own saved runtime receipt.
